# 签到机制与自动化说明

## 结论：签到默认走工作台；自动签到是可选项（v1.7.24）

签到（以及到期提醒）的**主入口仍在工作台**；自动签到是一个**默认关闭**的开关，
打开后由 **Windows 计划任务**每天定时完成，与工作台开不开无关。

| 能力 | 实现 | 触发方式 |
|------|------|----------|
| 每日签到 | 工作台顶部「立即签到」按钮（调 `GET /api/checkin`） | 打开工作台，未签到时**首次加载自动弹框引导** |
| 到期提醒 | 工作台首次加载弹框（阈值默认 24h，可自定义/关闭） | 打开工作台时自动检查 |
| **自动签到**（可选） | Windows 计划任务 → `auto_checkin.py run` | 工作台「设置 → 自动签到」开启；每天定时，**不依赖工作台** |

命令行等价用法（脚本仍保留，供手动/脚本调用）：

```
python <skill>/scripts/workbuddy_credits.py status    # 签到状态
python <skill>/scripts/workbuddy_credits.py checkin   # 签到（幂等）
python <skill>/scripts/auto_checkin.py install --time 09:30   # 注册计划任务（也可在工作台开关）
python <skill>/scripts/auto_checkin.py run                    # 立刻按计划任务的方式跑一次
```

## 为什么自动签到**默认关闭**

1. **它会写系统配置**：开启 = 在任务计划程序里创建一个任务。这属于「改动机器状态」，
   必须由用户自己点开关，不能默默发生。
2. **失败必须看得见**：签到可能因为会话过期失败。默认不开，用户就不依赖它；
   开了之后，失败会记在「自动签到」弹窗的「上次运行」里，而不是静默。
3. **多数人不需要**：签到幂等、成本极低，打开工作台时顺手一点即可。

所以它是**可选项而非默认行为** —— 想零操作的用户自己打开，其余人不受影响。

## 未签到提示的行为

- 触发条件：**当天未签到**，且工作台通过 HTTP（`serve.py`）访问。
- 只弹一次：每次打开工作台检查一次；会话内刷新不重复弹。
- 静态版（`file://`）不弹——该模式下无法调用签到接口，提示会误导。
- 弹框含「立即签到」按钮，点击后复用顶部按钮的签到逻辑（签到成功后自动刷新数据并置灰按钮）。

## 自动签到的实现与取舍（v1.7.24）

早期版本曾把「系统任务计划程序」列为**未采用**的可选替代，理由是三点：属系统级配置、
不随 skill 分发、机器关机时不执行。v1.7.24 把这三条都解决了：

| 原顾虑 | 现在 |
|---|---|
| 系统级配置、每台机器手工设 | 工作台一个开关代劳，`schtasks` 由脚本注册/删除 |
| 机器关机 / 未登录则不执行 | 任务配 `StartWhenAvailable` → 下次登录后补跑（InteractiveToken 必须有登录会话） |
| 失败没人看得到 | 结果写 `auto_checkin_log.json`，弹窗显示「上次运行」+ 失败原因 |

**为什么不用服务进程里的定时器**：工作台页面全部关闭约 75 秒后服务自己退出
（闲时看门狗，v1.7.13 收紧过）。定时器活在那个进程里，用户关掉页面就等于关掉自动签到，
而且不报任何错 —— 只表现为「开关开着、从没签上」。

实现细节与三条硬约束（`pythonw` 无 stdout、不能与工作台抢浏览器 profile、
`schtasks /XML` 只认 UTF-16 BOM）见 `dev-notes.md`「七、自动签到」。
