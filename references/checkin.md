# 签到机制与自动化说明

## 结论：签到统一走工作台，不使用定时任务

本 skill **不再配套任何定时任务**。签到（以及到期提醒）全部收敛到**工作台**里：

| 能力 | 实现 | 触发方式 |
|------|------|----------|
| 每日签到 | 工作台顶部「立即签到」按钮（调 `GET /api/checkin`） | 打开工作台，未签到时**首次加载自动弹框引导** |
| 到期提醒 | 工作台首次加载弹框（阈值默认 24h，可自定义/关闭） | 打开工作台时自动检查 |

命令行等价用法（脚本仍保留，供手动/脚本调用）：

```
python ~/.workbuddy/skills/workbuddy-credits/scripts/workbuddy_credits.py status    # 签到状态
python ~/.workbuddy/skills/workbuddy-credits/scripts/workbuddy_credits.py checkin   # 签到（幂等）
```

## 为什么弃用定时任务

1. **体感价值低**：定时任务只在 WorkBuddy 运行时可执行，本质是"帮用户点一下按钮"；而签到本身幂等、成本极低。
2. **有后台开销**：每次运行会新建一个任务会话，长期累积成会话垃圾（此前清理的 20 个归档会话中，15 个来自自动任务）。
3. **打扰不可控**：无法保证"零打扰"，且失败时用户不一定能看到。

改为工作台统一入口后：用户打开工作台 → 未签到则弹框引导 → 点一下即完成并自动刷新。路径短、结果可见、无后台残留。

## 未签到提示的行为

- 触发条件：**当天未签到**，且工作台通过 HTTP（`serve.py`）访问。
- 只弹一次：每次打开工作台检查一次；会话内刷新不重复弹。
- 静态版（`file://`）不弹——该模式下无法调用签到接口，提示会误导。
- 弹框含「立即签到」按钮，点击后复用顶部按钮的签到逻辑（签到成功后自动刷新数据并置灰按钮）。

## 可选替代：Windows 任务计划程序（未采用）

若希望**完全零操作、且不依赖 WorkBuddy 运行**，可用系统任务计划程序每日定时调用：

```
pythonw <skill>/scripts/workbuddy_credits.py checkin
```

优点：零会话、零 WorkBuddy 依赖。
未采用的原因：属系统级配置、不随 skill 分发（每台机器需单独设置），且机器关机时不执行。当前方案已能覆盖绝大多数场景，故不默认启用。
